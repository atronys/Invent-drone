# 02. Архитектура

## 1. Главный принцип: склад — структурированная среда

Ряды, проходы, секции и ярусы известны заранее (план склада, адреса из WMS). Поэтому **не решаем
общую задачу автономии в неизвестной среде** (исследование, произвольное 3D-планирование), а:
- берём известную геометрию (`layout`) как глобальную карту и основу маршрута;
- используем восприятие только для **безопасности** (препятствия) и **коррекции позы**.

Это главный рычаг эффективности проекта: он убирает месяцы работы над навигацией общего вида
(та самая «2D-навигация на фиксированной высоте» из статьи A, которую авторы сами называют
ограничением).

## 2. Системный контекст

```
             ┌──────────────── склад (on-prem) ───────────────┐
  WMS / 1С ◄─►│ Сервер INVENT (FastAPI + PostgreSQL)           │◄─► Веб-панель оператора
  выгрузка    │  • раскладка склада, расписание миссий         │    (фасады, расхождения,
  CSV → API   │  • приём сканов, сверка, отчёты                │     перескан, Excel)
             └───────────────────▲────────────────────────────┘
                                 │ Wi-Fi: только данные (автономия от сети не зависит)
             ┌───────────────────┴───┐          ┌──────────────────────┐
             │        Дрон           │◄────────►│ Док: старт, АКБ,     │
             └───────────────────────┘          │ огнестойкий бокс     │
                                                └──────────────────────┘
```

## 4. Системы координат

- `map` — ENU склада из `layout` (x вдоль рядов, y поперёк, z вверх, 0 — пол). В симуляции
  совпадает с `world` Gazebo.
- `odom` (VIO) → `base_link` → `camera_left`, `camera_right`, `camera_front`, `rangefinder`.
- PX4: локальный **NED** с началом в точке инициализации EKF (= док).
  ENU→NED: `(x, y, z) → (y, x, −z)`; курс `ψ_NED = π/2 − ψ_ENU` (реализовано в `mission_node`).
- Связка `map↔odom` задаётся стартом с дока (известная точка раскладки) и уточняется маркерами/
  этикетками (LOC-05, LOC-06).

## 6. Оптика этикеток — главный инженерный расчёт

```
px/мм      = W / (2 · d · tan(HFOV/2) · 1000)        W — ширина кадра, px; d — до фасада, м
px/модуль  = px/мм · X                              X — ширина модуля штрихкода, мм;  цель ≥ 2.5
смаз, мм   = v · t_exp · 1000                       держать ≤ 0.5·X
```

Дрон на оси прохода 3 м → d = 1.5 м; сенсор 12 Мп (4056 px). Команда:
`python -m invent_core optics --distance 1.5 --hfov <угол> --vfov <угол>`.

| Объектив (HFOV/VFOV) | px/мм | X = 0.5 мм | X = 1.0 мм | Кадр на фасаде | Макс. выдержка при 0.4 м/с (X = 0.5 / 1.0) |
|---|---|---|---|---|---|
| 50° / 39° (широкий, по умолчанию в `core`) | 2.90 | 1.45 ✗ | 2.90 ✓ | 1.40 × 1.06 м | 0.62 / 1.25 мс |
| 29.4° / 22.2° (≈12 мм на IMX477) | 5.15 | 2.58 ✓ | 5.15 ✓ | 0.79 × 0.59 м | 0.62 / 1.25 мс |
| 25° / 19° | 6.10 | 3.05 ✓ | 6.10 ✓ | 0.67 × 0.50 м | 0.62 / 1.25 мс |

**Выводы:**
1. SSCC-этикетка A6 (148×105 мм) несёт GS1-128 шириной ~70–100 мм при X ≈ 0.5–0.8 мм. Широкий
   объектив её **не прочитает** с оси прохода → нужен узкий (~25–30° на 12 Мп) или больше мегапикселей.
2. **Узкий кадр → узкая вертикальная полоса (~0.5 м) → нижний ярус не виден.** Планировщик это ловит:
   с объективом 29.4° и `min_z = 0.8 м` на демо-складе **не покрыто 120 из 480 ячеек** (весь нижний ярус,
   этикетки на 0.5 м). Варианты: вторая камера на сторону с наклоном вниз; наклон основной камеры
   на нижнем пролёте; `min_z` 0.5 м в изолированной зоне. Решение — задачи PER-01 и MIS-04.
3. Выдержка < 1 мс при складской освещённости требует **бортовой LED-подсветки со стробом** (PER-04).
4. **Первое, что измерить на реальном складе, — X на реальных этикетках** (BIZ-06): от этого
   зависят камера, объектив, высоты пролётов и скорость. Для SSCC в GS1-128 код содержит 156 модулей,
   поэтому X = ширина штрихов / 156 (78 мм → 0.5 мм) — см. `docs/custdev/site_survey_checklist.md`.
5. PnP по углам этикетки даёт **положение с точностью < 1%, а ориентацию — хуже** (до ~2.5° при ошибке
   углов 0.5 px, тест `core/tests/test_pnp.py`) → как наблюдение для локализации берём положение.

## 7. Планирование миссии (как устроено в `core/invent_core/coverage.py`)

1. Для каждого прохода: полоса обзора (высота кадра × (1 − поля)) → **жадное покрытие высот
   этикеток** отрезками этой длины (для 1D-покрытия жадный алгоритм оптимален) → высоты пролётов.
2. Точки сканирования вдоль оси с шагом ≤ ширины кадра; «змейка» по пролётам.
3. Переходы между проходами — через магистральный проезд на `transit_z`, носом по ходу.
4. Вылеты набираются жадно: пролёт добавляется, если после него АКБ (с резервом) хватает вернуться
   на док. Время отрезка консервативно: горизонталь + вертикаль + разворот последовательно.
5. Проверка покрытия: какие ячейки не попадут в кадр — предупреждение.

Демо-склад (2 прохода, 4 ряда × 10 секций × 4 яруса × 3 места = 480 ячеек; АКБ 10 мин, резерв 25%):
2 вылета по ~6 мин, **~2100 ячеек/ч** непрерывно или ~1300 ячеек/ч в stop-and-scan (1.5 с на точку).

Формально выбор пролётов при ограничении энергии — **orienteering problem** (NP-трудна); жадная
эвристика — baseline, улучшения и сравнение — MIS-07 (методология статьи V).

## 8. Безопасность (слои)

1. **Организационный:** полёты без людей и техники в зоне (ночь, огороженный проход), регламент, допуск.
2. **Геозона:** коридоры проходов из `layout` + геозона PX4; выход → зависание/посадка (SAFE-02).
3. **Пузырь безопасности:** фронтальная depth → стоп при препятствии ближе D_stop; боковые ToF —
   удержание дистанции до стеллажа (SAFE-01, SAFE-05).
4. **Failsafe PX4:** потеря Offboard-потока, позиции (VIO), низкий заряд, потеря связи → Hold/Land (SAFE-03).
5. **Железо:** защита винтов (обязательна), масса ≤ 1.5 кг, ограничение скорости, kill-switch на пульте.
6. **АКБ:** зарядка и хранение в огнестойком боксе на доке.

## 9. Модель данных

`Warehouse` → `RackRow` → `Location(address, x, z)`; `Aisle`; `Mission` (параметры плана) →
`Sortie` → `Waypoint(targets)`; `Observation(address, code, occupied, confidence, pose, кроп, t)`;
`WmsSnapshot(address → code)`; `LocationResult(status)`; `Report(IRA)`.

Статусы сверки: `OK`, `MISMATCH` (другая паллета), `MISSING` (пусто вместо паллеты), `UNEXPECTED`
(паллета вместо пустоты), `UNREADABLE` (паллета есть, этикетка не прочитана → перескан),
`NOT_SCANNED`; плюс примечания «паллета найдена в …» / «по WMS числится в …».
IRA (точность учёта) = OK / (ячейки с определённым результатом).
